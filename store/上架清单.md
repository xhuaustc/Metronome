## 二、只有你能做的四件事

### 第 1 步 · 在 App Store Connect 建 App 记录

必须先建记录，否则包传不上去（会报 "no app found"）。

1. 打开 <https://appstoreconnect.apple.com/apps>
2. 「我的 App」→ 左上角 **+** → **新建 App**
3. 填写：

   | 字段 | 值 |
   |---|---|
   | 平台 | iOS |
   | 名称 | `钢琴节拍器` |
   | 主要语言 | 简体中文 |
   | 套装 ID | `com.mpan.pianometronome`（下拉里已有，若没有说明 Bundle ID 还没注册，见下） |
   | SKU | `pianometronome001`（随便填，不对外可见） |
   | 用户访问权限 | 完全访问 |

   > 下拉里找不到套装 ID 时：去 <https://developer.apple.com/account/resources/identifiers> 
   > 注册一个 App ID，Bundle ID 填 `com.mpan.pianometronome`，勾选 App 即可。

---

### 第 2 步 · 上传构建版本

两条路，任选一条。

#### 路线 A：Xcode 图形界面（最快，不用配密钥）

```bash
open ~/WorkBuddy/节拍器/build/PianoMetronome.xcarchive
```

会自动打开 Xcode Organizer。然后在右上角点 **Distribute App** → **App Store Connect** → **Upload**。
签名用自动配置，一路 Next 即可。上传完大约 5–15 分钟出现在 App Store Connect 的「构建版本」里。

> 这条路线之所以能用，是因为 Xcode 图形界面能读到你已登录的开发者账号；
> 命令行读不到（这也是脚本导出时报 No Accounts 的原因）。

#### 路线 B：API 密钥 + 脚本（可重复，适合以后每次发版）

1. 打开 <https://appstoreconnect.apple.com/access/integrations/api>
2. 「团队密钥」→ **+** → 名称随意（如 `release`）→ 访问权限选 **App 管理**
3. 下载 `AuthKey_XXXXXXXXXX.p8`（**只能下载一次**），记下 Key ID 和 Issuer ID
4. 保存到固定位置并执行：

```bash
mkdir -p ~/.appstoreconnect/private_keys
mv ~/Downloads/AuthKey_XXXXXXXXXX.p8 ~/.appstoreconnect/private_keys/

export ASC_KEY_ID=XXXXXXXXXX
export ASC_ISSUER_ID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
export ASC_KEY_PATH=~/.appstoreconnect/private_keys/AuthKey_XXXXXXXXXX.p8

cd ~/WorkBuddy/节拍器
./store/scripts/release.sh
```

脚本会自动完成：归档 → 生成分发描述文件 → 导出 IPA → 校验 → 上传。
以后改完代码只要重跑这一条。

### 第 3 步 · 填写 App 信息

在 App Store Connect 的 App 页面，按 `store/listing-zh.md` 逐项粘贴：

- **App 信息**：名称、副标题、分类（音乐）、内容版权（`2026 Xiaohua Pan`）
- **价格与销售范围**：免费
- **App 隐私**：选「否，不收集数据」
- **年龄分级**：全部选「无」，结果 4+
- **版本信息**：描述、关键词、宣传文本
- **App 审核信息**：把 `listing-zh.md` 里「审核备注」那段贴进 Notes
- **截图**：上传 `store/screenshots/` 里那三张到「6.9 英寸显示屏」

**关于截图**：只需 6.9 英寸这一组，Apple 会自动缩放到其它尺寸。若想额外覆盖 6.5 英寸，可再跑一次 `SIM_UDID=<iPhone 11 Pro Max 的 UDID> ./store/scripts/screenshots.sh`。

### 第 4 步 · 托管隐私政策与支持页

App Store 要求填两个网址，缺一个都不能提交。

**用 GitHub Pages（免费）**：

1. 把仓库推到 GitHub（已配置 `git@github.com:xhuaustc/Metronome.git`）
2. 仓库 **Settings → Pages**
3. Source 选 **Deploy from a branch**，Branch 选 `main`，目录选 **/docs**，Save
4. 等 1–2 分钟，得到：
   - 隐私政策网址：`https://xhuaustc.github.io/Metronome/privacy.html`
   - 技术支持网址：`https://github.com/xhuaustc/Metronome`

> 私有仓库要开 Pages 需要 GitHub Pro。若不想公开源码，可以把 `docs/privacy.html` 
> 单独放到任意静态托管（Vercel、Cloudflare Pages、语雀、自己的域名都行），只要是个能打开的 https 链接。

## 三、提交前必须做的一个决定：中国大陆

2023 年 9 月起，App 要在中国大陆区上架，需要提供 **ICP 备案号**。这个应用完全离线、没有服务器和域名，备案会很麻烦。

建议：

- **第一次提交**：在「价格与销售范围」里把**中国大陆取消勾选**，先让海外区过审。审核通过后随时可以再勾回来。
- 如果一定要上中国大陆：需要先给一个域名做 ICP 备案，在 App Store Connect 里填备案号。这是纯行政流程，和应用本身无关。

## 四、提交审核

1. 版本页面右上角 **添加构建版本**，选中刚才上传的那个
2. 确认没有黄色感叹号（有的话按提示补，通常就是上面那些网址和截图）
3. 右上角 **提交审核**
4. 首次审核一般 24–48 小时

审核被拒最常见的两点，以及本项目的应对：

| 常见理由 | 本项目的应对 |
|---|---|
| Guideline 2.5.4 后台音频滥用 | 审核备注已说明「锁屏继续播放是钢琴练习的实际需要」，并给了复现步骤 |
| Guideline 4.2 功能过于简单 | 描述里强调了零漂移调度、6/8 分组重音、播放中变速不补响等实现难度 |

## 六、备注：本机构建的两个坑

1. `xcodebuild` 必须在 `OTHER_SWIFT_FLAGS` 里加 `-Xfrontend -disable-sandbox`，
   否则编译器给宏插件套 sandbox 会被拒，报 `SwiftUIMacros.StateMacro could not be found`。
   两个脚本里都已经带上了。
2. 命令行读不到 Xcode 的开发者账号（`No Accounts`），所以导出分发包要么走 API 密钥，
   要么走 Xcode 图形界面。归档本身不需要账号。

## 七、当前阻塞：开发者协议未签署（最重要）

2026-11-03 实测，App Store Connect API 对所有会员资源返回：

```
HTTP 403  FORBIDDEN_ERROR.PLA_NOT_ACCEPTED
"your team's Account Holder, Xiaohua Pan, must agree to the latest Program License Agreement."
```

含义：Apple 更新了《Apple Developer Program License Agreement》，团队 Account Holder 必须重新签署一次。
**未签署前，一切都会被挡住**——注册 Bundle ID、生成分发描述文件、上传包、提交审核，全部返回 403。
这也解释了 `xcodebuild -exportArchive` 为什么报 "Unable to process request - PLA Update available"。

### 解除方式（只能由 Account Holder 本人操作）

1. 打开 <https://developer.apple.com/account>
2. 用 Account Holder 的 Apple ID 登录（含双重认证）
3. 首页顶部或「协议、税务和银行业务」里会有待同意的协议横幅，点 **Review Agreement** → 勾选 → **Agree**
4. 有时 App Store Connect 里也要签一次：<https://appstoreconnect.apple.com/agreements>

签完立刻生效，不需要等审核。之后 API 与 `xcodebuild` 就能正常创建描述文件和上传。

### 签署后的顺序

1. 先确认 App 记录是否已存在（API 查询 `GET /v1/apps`）。
   **App 记录无法通过 API 创建**，没有对应端点，必须在网页里点「+ 新建 App」。
2. 建好后，其余步骤都可以走 `store/scripts/release.sh` + API，不需要网页。
