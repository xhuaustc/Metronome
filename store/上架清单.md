## 一、这次真正打通链路的三处改动

前三轮都卡在同一类问题：自动签名在 Individual 团队不可用。现在全部绕开了。

### 1. 分发描述文件改为 API 手动创建

`xcodebuild -exportArchive` 原本报 `You haven't been given access to
cloud-managed distribution certificates`。Individual 团队拿不到云管理的分发证书，
`-allowProvisioningUpdates` 只会让它去碰那条走不通的路。

改为用 App Store Connect API 以本地已有的 iOS Distribution 证书
（`Y6BBL6RBVL`，序列号 `65ED0CE6…`，私钥在本机钥匙串）创建描述文件，
下载后装进 `~/Library/MobileDevice/Provisioning Profiles/`。
`Support/ExportOptions.plist` 相应改为 `signingStyle = manual`。

### 2. 部署目标回退到 16.0 后重新归档

归档、导出、`altool --validate-app` 均一次通过。

### 3. 元数据全部走 API 写入

网页端要面对三十多个年龄分级开关、三张截图的切片上传，手工点容易漏。
`fill-metadata.py` 与 `upload-screenshots.py` 把这一步变成可重跑的脚本。

## 三、API 上踩到的三个坑

记下来，下次改版本时不用重新试。

1. **截图槽位只有一个是对的：`APP_IPHONE_65`。** 枚举里能传 `APP_IPHONE_67`，
   尺寸校验也放行（1320×2868 传得进去、状态也是 COMPLETE），但**网页端不渲染这个槽位**——
   App Store Connect 的「App 预览和屏幕快照」会显示成完全空白，看起来像没上传。
   教训：接口说 COMPLETE 不等于页面上看得见。用 `APP_IPHONE_65`（1284×2778），
   这是网页端实际显示、且已上线的 Gleamory Pro 也在用的槽位。
   另外 `APP_IPHONE_69` 在 API 里不存在，6.9 英寸只能在网页端传。
2. **切片上传不能带 `Authorization` 头。** 预签名 URL 的鉴权在 query string 里，
   多补一个 Bearer 会让签名失配，S3 回 400 `Invalid request`。
3. **年龄分级字段类型不统一。** 13 个是三档枚举（`NONE` / `INFREQUENT_OR_MILD` /
   `FREQUENT_OR_INTENSE`），11 个是布尔。混着传直接 409。

「App 隐私」问卷没有公开 API，只能在网页端填。填完要单独点一次 Publish，
否则提交时会报 `STATE_ERROR.APP_DATA_USAGES_REQUIRED`。

## 四、审核阶段可能被问到的事

### 中国大陆区备案适用性待确认

销售范围包含中国大陆。离线属性不能单独证明备案豁免，也不能据此断言一定需要备案；
应向 Apple 或主管部门确认本应用的适用要求，详见第九节。

### 后台播放是审核员最常追问的点

审核备注里已写明 `UIBackgroundModes = audio` 的用途和复现步骤。
若仍被追问，直接引用那三段话。

### 被拒后的处理

拒绝原因会出现在 App Store Connect 的「App 审核」页。改完重新上传一个构建
（构建号 +1，改 `PianoMetronome.xcodeproj` 里的 `CURRENT_PROJECT_VERSION`），
再跑一次 `release.sh` 即可，元数据不用重填。

## 七、本机构建的两个坑（沿用之前记录）

1. `xcodebuild` 必须在 `OTHER_SWIFT_FLAGS` 里加 `-Xfrontend -disable-sandbox`，
   否则编译器给宏插件套 sandbox 会被拒，报 `SwiftUIMacros.StateMacro could not be found`。
   脚本里已经带上了，不要写进 pbxproj。
2. 命令行读不到 Xcode 的开发者账号（`No Accounts`），所以导出分发包走 API 密钥。
   归档本身不需要账号。

Apple 说明中国大陆部分 App 需要有效 ICP 备案号，具体情形需向 Apple 或主管部门确认：
<https://developer.apple.com/cn/help/app-store-connect/reference/app-information/app-information>。

此前的静态核查记录：

| 核查项 | 方法 | 结果 |
|---|---|---|
| 源码里的网络调用 | grep `URLSession\|URLRequest\|dataTask\|NWConnection\|WKWebView\|CFSocket\|NSNetService` 等 | 0 处 |
| import 的框架 | 遍历 `Metronome/**/*.swift` | 只有 Foundation / SwiftUI / UIKit / AVFoundation |
| 链接的动态库 | `otool -L` 已签名二进制 | 无 CFNetwork，仅 Foundation / AVFAudio / Combine / CoreFoundation / SwiftUI / UIKit |
| 二进制内的 URL | `strings -a` 过滤 `https?://` | 0 条 |
| ATS 配置 | `Support/Info.plist` | 无 `NSAppTransportSecurity` 任何键 |
| 能力与授权 | 全工程找 `*.entitlements`、`CODE_SIGN_ENTITLEMENTS` | 两者皆无 |
| 隐私清单 | `Metronome/PrivacyInfo.xcprivacy` | `NSPrivacyTracking=false`、`NSPrivacyCollectedDataTypes` 为空、仅 UserDefaults（CA92.1） |

隐私清单与已填写的「不收集数据」声明一致；但静态搜索、未显式链接 CFNetwork、
未配置 ATS 或未发现 URL，均不能单独证明不存在任何网络访问。以上也不构成备案豁免证明。

**若收到备案要求**：如实说明应用离线功能和实际服务情况，向 Apple 或主管部门
咨询适用要求及是否可以申请豁免，并根据正式回复处理。
